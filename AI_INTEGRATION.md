# Инструкция для ИИ разработчика

Источник — `assets.json`: выберите валюту и прочитайте указанный `latest_path`. Корневой `latest.json` относится только к ETH. Все пути в указателях относительны корню репозитория. Конкретный адрес размещения задаётся при подключении источника.

1. Зафиксировать один Git SHA ветки и прочитать `assets.json`, указатель выбранной валюты, `manifest.json` и `chart.json` по этому SHA. Проверить SHA-256 и размер файлов по манифесту; сверить `chart_sha256` и `release_id`. Сервер сайта может хранить последний проверенный комплект в кэше и заменять его целиком после успешной проверки. Не смешивать файлы разных выпусков.
2. Построить два отдельных графика из `series`: CALL и PUT, с одинаковым масштабом APY. Ось X — `distance_usd` в долларах; ось Y — `mean_cost_pct` в процентах годовых. Значения уже выражены в процентах: **117.34 означает 117.34% годовых; не умножать на 100**. Меньшие расходы лучше. Ноль и отрицательные числа допустимы; не применять модуль и не обрезать отрицательные значения.
3. Отобразить все средние из `series[].points` отдельными точками. Две сглаженные линии взять из `series[].trend`: X — `distance_usd`, Y — `cost_pct`. Координаты линии не являются дополнительными наблюдениями. Интерполировать только внутри опубликованного диапазона; формулу линии заново не подбирать. Начиная с выпуска `2026-10-02-v2`, координаты рассчитаны по логарифмической модели `a + b*ln(distance_usd)` с натуральным логарифмом. Оси остаются линейными. Для промежуточного расстояния сайт и бот используют линейную интерполяцию соседних опубликованных координат `trend`; это приближение логарифмической кривой, а не интерполяция средних `points`.
4. В основном виде показать период из `sample`, число недель, выбранное расстояние и средние расходы по обоим направлениям. Рядом — «Недели с хеджированием», «Открытия защитной позиции», «Недели без сделок». Краткие определения брать из `interpretation_ru`. Для дат использовать даты завершения недель, не дату публикации.
5. В раскрываемом разделе «Выборка и устойчивость» показать состав и причины исключений только внутри периода sample.expiry_from–sample.expiry_through, медиану, диапазон средней половины недель и диапазон среднего без одной недели. Эти показатели описательные; не подписывать их как доверительные интервалы или вероятность успеха. Число сценариев и периодов истории брать из текущего sample.
6. Факторы брать из `factors_ru`; общие пояснения для посетителей — из `DESCRIPTION_RU.md` (описание относится к ETH; для BTC/SOL используйте соответствующие asset, sample и interpretation_ru из выбранного chart.json). **Не добавлять под графиком заключительный абзац, начинающийся «Оценка на прошлой…».** Не выводить автоматически весь `evidence_ru` в нижний блок интерфейса. Фактические даты, состав выборки и определения статистики остаются доступными.
7. Обрабатывать отсутствие данных отдельно от нуля. `null` — отсутствующее значение; `0` — действительный ноль. `weeks_without_entry_scenario` означает отсутствие подходящего сценария, такие случаи не заменять нулевыми расходами. При недоступном или невалидном обновлении сохранить последний проверенный выпуск и его фактические даты.

## Поля точки

| Поле | Значение |
| --- | --- |
| `distance_usd` | Удаление от страйка, USD |
| `mean_cost_pct` | Средние расходы, % годовых |
| `weeks_in_average` | Число недель в среднем |
| `weeks_with_hedging` | Недели хотя бы с одним открытием |
| `hedge_openings` | Число открытий защитной позиции |
| `weeks_without_trades` | Наблюдаемые недели без открытий |
| `weeks_without_entry_scenario` | Недели без подходящего сценария |
| `median_week_cost_pct` | Медиана недельных расходов |
| `middle_half_week_cost_pct` | Границы средней половины результатов |
| `historical_week_range_cost_pct` | Минимум и максимум недельных расходов |
| `mean_omit_one_week_cost_pct` | Границы среднего при исключении одной недели |

## Проверка внедрения

Все средние должны совпасть с `chart.csv`. В выпуске `2026-09-13-v2` при $25: CALL — 117.33787836939413% годовых, 11 из 14 недель с хеджированием, 96 открытий, 3 недели без сделок; PUT — 69.75019001014341% годовых, 8 из 14, 43 открытия, 6 недель без сделок. Для следующих выпусков брать значения из нового комплекта.

Проверить подсказки для обоих направлений, управление с клавиатуры и касанием, ширину 320 px, нулевые и отрицательные расходы, отсутствие данных и отказ обновления. Интерфейс использует только опубликованные поля; дополнительные торговые настройки для построения графика не нужны.



## Выпуск 2026-10-05-v1 и потребители данных

Текущий выпуск содержит 22 средних: по 11 для CALL и PUT, расстояния $5, $10, $12.5, $15, $20, $25, $35, $45, $55, $65, $75; 18 доступных недель, 396 сценариев. Диапазон, число расстояний и недель всегда считывать из JSON. Структура схемы 1.0.0 и названия полей не менялись.

Бот использует те же percent_per_year: 100 означает 100% годовых расходов, а не коэффициент 100. Для сопоставления с премией обе величины должны быть приведены к одной базе капитала и фактическому времени до экспирации. Эти данные не включают премию опциона. Не применять abs(), не удваивать годовой пересчёт, не экстраполировать за пределы trend. Статистику открытий и недель между опубликованными расстояниями не выдумывать; она относится к points.


В этой ревизии изменены только метаданные исключений и описания; все расчётные значения и CSV совпадают с 2026-10-04-v2. sample.excluded содержит только пропуски внутри опубликованного периода. Даты до начала выборки не входят в этот список и не должны выводиться как недоступные недели. Шестимесячное окно накапливается со временем; меньшая текущая длина сама по себе не является ошибкой. Не подставлять данные старого выпуска или старую формулу `a+b/x`, не переключать ось в логарифмический масштаб вместо замены кривой, не экстраполировать за опубликованный диапазон.

## Выбор валюты

Каталог [assets.json](assets.json) явно сопоставляет валюту с её постоянным указателем:

| Валюта | Постоянная точка входа |
| --- | --- |
| ETH | [latest.json](latest.json) |
| BTC | [assets/BTC/latest.json](assets/BTC/latest.json) |
| SOL | [assets/SOL/latest.json](assets/SOL/latest.json) |

Все пути внутри указателей относительны корню репозитория. У всех трёх валют данные выпусков хранятся в `releases`; потребитель читает актуальный путь из соответствующего `latest.json`, а не закрепляет папку выпуска в коде. Корневой `latest.json` остаётся указателем ETH для совместимости. Проверяйте `asset` в chart.json перед отображением. Не подставляйте данные одной валюты вместо другой.
