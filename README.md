# Данные графиков расходов на хеджирование

Проверенные данные для hedgebot.io и расчёта ожидаемых расходов на хеджирование. Два направления: CALL — хедж при росте цены; PUT — хедж при падении цены. Расходы приведены к году; меньше — дешевле. Премия опциона в эти расходы не входит.

- [assets.json](assets.json) — каталог валют и постоянных точек входа.
- [AI_INTEGRATION.md](AI_INTEGRATION.md) — контракт загрузки, единиц и отображения.
- [DESCRIPTION_RU.md](DESCRIPTION_RU.md) — описание для посетителей.

Выпуск `2026-10-05-v1`: 18 доступных недель с экспирациями 29.05–02.10.2026, одиннадцать расстояний $5, $10, $12.5, $15, $20, $25, $35, $45, $55, $65, $75; 22 средних и 396 недельных сценариев. Неделя 07.08.2026 исключена из-за недостаточной исходной истории. Расстояния и стороны используют одни и те же 18 недель.

Каждый выпуск содержит `chart.json`, `chart.csv` и `manifest.json` с размерами и SHA-256. Схема данных 1.0.0 сохранена. Число точек и диапазон читаются из выпуска и не должны быть зафиксированы в коде потребителя.

Обновления планируются по субботам после проверки новой завершённой недели. Настройки заново выбираются по принятым полным неделям. История накапливается с новыми завершёнными неделями до шестимесячного календарного окна, затем окно сдвигается. Исключения показываются только внутри опубликованного периода выборки. Старые выпуски сохраняются; указатель меняется атомарно после проверки. При задержке остаётся предыдущий проверенный выпуск с его фактическими датами.

В выпуске `2026-10-05-v1` уточнён только список исключений: даты до начала выборки в него не входят. Расчётные значения полностью совпадают с выпуском `2026-10-04-v2`. Линии рассчитаны как `a + b*ln(x)`, где `x` — расстояние в USD. Сайт и бот используют опубликованные координаты `series[].trend` внутри диапазона $5–75.

## Выбор валюты

Каталог [assets.json](assets.json) явно сопоставляет валюту с её постоянным указателем:

| Валюта | Постоянная точка входа |
| --- | --- |
| ETH | [assets/ETH/latest.json](assets/ETH/latest.json) |
| BTC | [assets/BTC/latest.json](assets/BTC/latest.json) |
| SOL | [assets/SOL/latest.json](assets/SOL/latest.json) |
| HYPE | [assets/HYPE/latest.json](assets/HYPE/latest.json) |

Все валюты используют единую схему: `assets/<TICKER>/latest.json` → `assets/<TICKER>/releases/<release_id>/`. Единственный каталог монет — `assets.json`; все пути указателей относительны корню репозитория. Потребитель фиксирует один SHA ветки `main`, читает каталог и следует `latest_path`, затем manifest/chart по тому же SHA. Нельзя хардкодить особые пути ETH или подставлять данные другой монеты. Поле `asset` обязательно в указателе и после приведения к верхнему регистру совпадает с ключом каталога и `chart.asset`; `release_id` совпадает во всех трёх файлах. В manifest пути файлов — basename (`chart.json`, `chart.csv`), размеры и SHA-256 проверяются по фактическим байтам.

### Переходный период (вариант B)

Корневой `latest.json` **deprecated**: временно это байт-в-байт копия `assets/ETH/latest.json`, уже указывающая на `assets/ETH/releases/`. Он будет удалён при следующем обновлении ETH. Новые потребители обязаны использовать только `assets.json`. Корневой `releases/` остаётся историческим архивом без активного указателя; новые выпуски всех монет публикуются только в `assets/<TICKER>/releases/`. `DESCRIPTION_RU.md` остаётся общим корневым текстом, исторически об ETH, и не входит в per-asset layout.
